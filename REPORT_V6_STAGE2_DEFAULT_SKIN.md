# SlotNet V6 Stage 2 — Copy Head Only, One Skin

Date: 2026-05-23

## Conclusion

V6 learns BMP-pixel → input-pixel correspondence at sub-pixel accuracy with
the provenance-derived labels. This validates the V6 mechanism and the
final-frame provenance + label generation pipeline.

It does **not** clear the full Stage 2 acceptance bar. UV is well below the
target; visible-pixel MAE is plateaued ~2.5× above target; AUC sits one
delta below target.

```text
UV correspondence (uv_median_px < 2)        PASS    0.66 vs 2.0 target
copy quality (visible_mae < 0.01)           PARTIAL 0.0251 vs 0.01 target
identity confidence (copy_conf_auc > 0.98)  FAIL    0.968 vs 0.98 target
```

Best checkpoint:

```text
runs/slotnet_v6_default_skin_stage2_p3subpx/snapshot_step002000.safetensors
```

This is the artifact downstream Stage 3+ experiments should resume from.

## What the run proved

The Stage 2 question was: *can the V6 architecture learn precise
correspondence between an exported BMP pixel and the canvas pixel where it
appears in a rendered view?* The answer is unambiguously yes.

Aggregate `uv_median_px = 0.66` means the typical exported pixel's UV
target lands inside the source pixel's own canvas cell — the V6 model can
identify the source location with sub-pixel accuracy on a one-skin
overfit. Eleven of eleven trainable files reach `uv_median_px < 1.1`. The
worst is EQMAIN at 0.99.

This is the central claim V6 was designed to test, and it passes.

## What the run did not prove

`visible_mae` plateaued at 0.025, not 0.01. The user-side bilinear vs.
nearest cross-check on the best checkpoint:

```text
visible_mae (bilinear grid_sample, production mode)   0.0251
visible_mae (nearest grid_sample, label-semantics)    0.0212
```

So roughly 30% of the residual visible MAE is bilinear blur from
sub-pixel UV imprecision, and 70% lives in something nearest can't fix —
genuine pixel-value mismatch even when the model points at the right
canvas cell. That residual is what `copy_residual` is meant to handle in
the next probe.

UV tail matters too. The median is excellent, but the worst file still
has a long upper tail:

```text
EQMAIN uv error distribution (best checkpoint)
  p50    0.98 px
  p90    3.15 px
  p95    4.80 px
  p99   11.76 px
```

Stage 2 acceptance is "median" only, so the tail does not invalidate the
pass on UV correspondence, but it does tell us where the next failure
mode will surface: under a strict per-pixel evaluation, ~5% of EQMAIN
pixels still mispoint by 4+ canvas pixels.

## Lessons used in the run

These were resolved during this trajectory and are now baked into the
training infrastructure.

```text
1. Default V6 plan weights (uv_loss=normalized, beta=0.1) cannot learn
   precise UV because beta=0.1 in normalized space = 96 px in input
   coords. Switched to uv_loss=pixel with beta_px scaled to the
   acceptance target.

2. UV-first (copy_rgb weight = 0) gets UV into a sane range first; only
   then does copy_rgb pulling on UV become productive instead of
   competitive.

3. AdamW state is not checkpointed, only weights. Resuming has a brief
   loss bump (~18% on UV at step 0); harmless but explains the 28k →
   29k → 30k wobble in phase 1+.

4. The 25k → 30k EQMAIN UV regression looked structural at first; per-
   step inspection (25k, 26k, 27k, 28k, 29k, 30k) showed it was
   optimizer/checkpoint volatility, not a real per-file failure.
   step-28k was the clean phase 1 endpoint.

5. Subpixel UV refinement (beta_px=0.5) drops UV from ~1.3 to ~0.66 in
   1000 steps. Recipe saturates around 0.66 px median; further UV gain
   needs different conditioning, not more steps.

6. visible_mae cannot drop below ~0.025 with UV alone, even at 0.66 px
   median. The next step is a residual head, not more UV training.
```

## Next experiment

Per the user's call: a `copy_residual` probe, not more UV training or
more balanced training. The V6 plan's full architecture has

```text
copy_refined = clamp(copy_rgb + residual_scale * tanh(copy_residual), 0, 1)
```

with `residual_scale = 0.25`. Stage 2 deferred this until the sampler was
proven. The sampler is now proven; the residual is the right next
mechanism to test whether the remaining ~0.02 visible MAE is correctable
without going to a full fallback / completer head.

Probe recipe (planned, from the best checkpoint):

```text
resume   runs/slotnet_v6_default_skin_stage2_p3subpx/snapshot_step002000.safetensors
model    same SlotNetV6 + new residual head (zero-init)
lr       1e-5
weights  copy_refined 1.0
         uv 0.5
         conf 0.25
         uv_tv 0.0005
         residual_l1 0.02 - 0.05
uv_loss  pixel, beta_px 0.5
steps    max 5k, eval every 1k

pass     visible_mae < 0.01
         uv_median_px stays < 2
         AUC does not collapse
```

Fallback / completer is explicitly out of scope for this probe.
